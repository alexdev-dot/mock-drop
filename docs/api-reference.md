# API Reference

This document describes all the REST API endpoints automatically generated by mock-drop.

## Base URL

By default, mock-drop runs on:
```
http://localhost:3000
```

Use the `--port` option to change the base URL:
```bash
mock-drop db.json --port 8080
# Base URL: http://localhost:8080
```

## Root Endpoint

### GET /

Returns information about available endpoints.

**Response:**
```json
{
  "message": "mock-drop API",
  "endpoints": [
    {
      "resource": "users",
      "methods": ["GET", "POST", "PUT", "DELETE"]
    },
    {
      "resource": "posts",
      "methods": ["GET", "POST", "PUT", "DELETE"]
    }
  ]
}
```

## Collection Endpoints

### GET /:resource

Retrieves all items in a resource collection.

**Example:**
```bash
GET /users
```

**Response:**
```json
[
  { "id": 1, "name": "Alice", "email": "alice@example.com" },
  { "id": 2, "name": "Bob", "email": "bob@example.com" }
]
```

**Query Parameters:**
You can filter results using query parameters:
```bash
GET /users?name=Alice
GET /users?age=25&active=true
```

**Status Codes:**
- `200 OK` - Success
- `404 Not Found` - Resource does not exist

### POST /:resource

Creates a new item in the resource collection.

**Example:**
```bash
POST /users
Content-Type: application/json

{
  "name": "Charlie",
  "email": "charlie@example.com"
}
```

**Response:**
```json
{
  "id": 3,
  "name": "Charlie",
  "email": "charlie@example.com"
}
```

**Status Codes:**
- `201 Created` - Item created successfully
- `400 Bad Request` - Invalid request body
- `404 Not Found` - Resource does not exist

**Note:** The `id` field is auto-generated if not provided.

## Resource Endpoints

### GET /:resource/:id

Retrieves a specific item by ID.

**Example:**
```bash
GET /users/1
```

**Response:**
```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com"
}
```

**Status Codes:**
- `200 OK` - Success
- `404 Not Found` - Item does not exist

### PUT /:resource/:id

Updates an existing item.

**Example:**
```bash
PUT /users/1
Content-Type: application/json

{
  "name": "Alice Updated"
}
```

**Response:**
```json
{
  "id": 1,
  "name": "Alice Updated",
  "email": "alice@example.com"
}
```

**Status Codes:**
- `200 OK` - Item updated successfully
- `404 Not Found` - Item does not exist

**Note:** The `id` field cannot be changed.

### DELETE /:resource/:id

Deletes an item from the collection.

**Example:**
```bash
DELETE /users/1
```

**Response:**
```json
{
  "id": 1,
  "name": "Alice",
  "email": "alice@example.com"
}
```

**Status Codes:**
- `200 OK` - Item deleted successfully
- `404 Not Found` - Item does not exist

## Nested Resource Endpoints

Nested resources allow you to model hierarchical data structures.

### GET /:resource/:id/:nestedResource

Retrieves all nested items for a parent resource.

**Example:**
```bash
GET /users/1/posts
```

**Response:**
```json
[
  { "id": 1, "title": "Alice's Post" },
  { "id": 2, "title": "Another Post" }
]
```

**Query Parameters:**
```bash
GET /users/1/posts?published=true
```

**Status Codes:**
- `200 OK` - Success
- `404 Not Found` - Parent or nested resource does not exist

### GET /:resource/:id/:nestedResource/:nestedId

Retrieves a specific nested item.

**Example:**
```bash
GET /users/1/posts/1
```

**Response:**
```json
{
  "id": 1,
  "title": "Alice's Post"
}
```

**Status Codes:**
- `200 OK` - Success
- `404 Not Found` - Parent or nested item does not exist

### POST /:resource/:id/:nestedResource

Creates a new nested item.

**Example:**
```bash
POST /users/1/posts
Content-Type: application/json

{
  "title": "New Post",
  "published": true
}
```

**Response:**
```json
{
  "id": 3,
  "title": "New Post",
  "published": true
}
```

**Status Codes:**
- `201 Created` - Nested item created successfully
- `400 Bad Request` - Invalid request body or nested resource is not an array
- `404 Not Found` - Parent resource does not exist

### PUT /:resource/:id/:nestedResource/:nestedId

Updates a nested item.

**Example:**
```bash
PUT /users/1/posts/1
Content-Type: application/json

{
  "title": "Updated Post"
}
```

**Response:**
```json
{
  "id": 1,
  "title": "Updated Post"
}
```

**Status Codes:**
- `200 OK` - Nested item updated successfully
- `404 Not Found` - Parent or nested item does not exist

### DELETE /:resource/:id/:nestedResource/:nestedId

Deletes a nested item.

**Example:**
```bash
DELETE /users/1/posts/1
```

**Response:**
```json
{
  "id": 1,
  "title": "Alice's Post"
}
```

**Status Codes:**
- `200 OK` - Nested item deleted successfully
- `404 Not Found` - Parent or nested item does not exist

## Query Parameter Filtering

### Syntax

Filter using query parameters on any `GET` endpoint:

```bash
GET /resource?field=value&field2=value2
```

### Supported Types

**String Fields:**
```bash
GET /users?name=Alice
```
- Case-insensitive comparison

**Number Fields:**
```bash
GET /users?age=25
```
- Numeric comparison

**Boolean Fields:**
```bash
GET /users?active=true
GET /posts?published=false
```
- Accepts `true` or `false` (case-insensitive)

### Multiple Filters

Multiple filters use AND logic (all must match):

```bash
GET /users?name=Alice&age=25&active=true
```

This returns users where:
- name equals "Alice" (case-insensitive)
- age equals 25
- active equals true

### No Matches

If no items match the filters, an empty array is returned:

```json
[]
```

## Error Responses

All error responses follow this format:

```json
{
  "error": "Error message"
}
```

### Common Errors

| Status Code | Error Message | Description |
|-------------|---------------|-------------|
| 400 | Request body is required | POST request without body |
| 400 | Nested resource is not an array | Attempting to POST to non-array nested resource |
| 404 | Endpoint not found | Resource does not exist |
| 404 | Item not found | Resource item with given ID does not exist |
| 404 | Parent item not found | Parent resource for nested route does not exist |
| 404 | Nested resource not found | Nested resource does not exist |
| 404 | Nested item not found | Nested item with given ID does not exist |
| 500 | Internal server error | Unexpected server error |

## CORS

All endpoints include CORS headers, allowing requests from any origin. This includes:

- `Access-Control-Allow-Origin: *`
- Standard CORS preflight handling

## Request Headers

### Content-Type

For POST and PUT requests, set the Content-Type header:

```
Content-Type: application/json
```

### Accept

Specify the response format (currently only JSON is supported):

```
Accept: application/json
```

## Response Headers

Standard HTTP headers are included in all responses:

- `Content-Type: application/json`
- CORS headers (if applicable)
- Other standard Express.js headers

## Limitations

- **No authentication**: All endpoints are publicly accessible
- **No pagination**: All items are returned (use query filters to limit results)
- **No sorting**: Results are returned in the order they appear in the JSON file
- **No relationships**: Foreign key relationships are not enforced
- **In-memory only**: Changes via POST/PUT/DELETE are lost on server restart
- **No validation**: Request bodies are not validated against a schema
